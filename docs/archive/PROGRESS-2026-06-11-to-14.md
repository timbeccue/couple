## 2026-06-13 — Audio-matching prework, Phase 3 (PLAN-AUDIO-MATCHING-PREWORK §8): verifier evidence independent + robust

Phase 3 of `PLAN-AUDIO-MATCHING-PREWORK.md`. Makes the fine verifier's evidence (a) UNIQUE —
windows are placed inside one global feasible interval instead of evenly-spaced-then-clamped,
so several centers can no longer collapse onto the same file edge and double-count one
measurement (§2.3) — and (b) ROBUST — a deterministic MAD outlier rejection wraps the ridge
line fit, so one or two false local locks cannot bias the offset/drift (§2.4). The match
predicate's minimum-count condition now uses the robust inlier count, not the raw locked count.
Phases 0–2 are the baseline; Phase 4 (candidate-overflow) NOT started. The experimental verifier
flag stays OFF by default (invariant 6), so default-off resolver behavior is unchanged.

**§8.1 — `verification_centers` replaces per-center clamping.** New private fn in
`core/src/verify.rs` with the plan's exact 8-arg signature. It computes ONE feasible interval
`[lo, hi]` from the MAXIMUM scan margin (`lo = max(overlap_t0, half_win, half_win − off + margin)`,
`hi = min(overlap_t1, dur_a − half_win, dur_b − off − half_win − margin)`), returns empty when
`hi < lo`, one midpoint when `desired == 1` or `hi − lo < 1e-9`, else exactly `desired` linearly
spaced points INCLUDING both endpoints, then dedups adjacent values closer than one 96-spb bin.
A nominal center is NEVER clamped: when the interval is too small to hold `desired` unique points,
fewer come back and the verifier reports an unmatched fit (never manufactures evidence). The
window-scan loop is otherwise unchanged (same measurability + NCC-floor lock test).

**§8.2 — `core/src/robust_fit.rs` (new module, registered in `lib.rs`).** `RobustFit { off_ms,
ppm, rms_ms, residual_p95_ms, clamped, inlier_indices }` + `fit_line_mad(points, lambda_s2,
max_ppm, absolute_floor_ms)`. The exact 10-step procedure: initial `fit::fit_ls_reg` → abs
residuals → median `m` → `MAD = median(|resid − m|)` → `sigma = 1.4826·MAD`, `threshold =
max(absolute_floor_ms, 3·sigma)` → keep inliers → refit → repeat steps 2–7 ONCE → require ≥ 2
inliers with non-degenerate t-spread (else `None`) → RMS from the final refit + nearest-rank p95
over the final inliers. `off_ms/ppm/rms_ms/clamped` are the final refit's `FitReg` fields (so
`clamped` still means "drift hit the bound" — a rejection signal). NO RNG, NO hash iteration, NO
wall clock; medians sort by `f64::total_cmp` and the fit sums are commutative ⇒ order-reversal is
bit-identical (invariant 3). `absolute_floor_ms` is passed in from `params.verify_outlier_floor_ms`
(= 2.0), never hardcoded inside the fitter. `inlier_indices` stays ascending (each filter
preserves input order) so the caller maps each survivor straight back to its center time.

**§8.3 — temporal coverage over the robust inliers.** `verify.rs::temporal_coverage_of_times`
now takes the inlier center times (recovered via `inlier_indices`) and reports
`(max − min) / max(overlap, ε)`. TELEMETRY ONLY — NOT added to the match predicate this phase
(awaits corpus evidence, §8.3). The p95 helper moved into `robust_fit.rs` (computed over the same
inlier set); the old `verify.rs::p95_abs_residual_ms` is deleted.

**§8.4 — corrected lock accounting.** `expected` = unique measurable placed centers (unchanged);
`locked` = those clearing the NCC floor (unchanged); `lock_fraction = locked/expected` (UNCHANGED
meaning); `inliers` = the §8.2 robust survivors (a subset of `locked`). `VerifyFit.matched` now
uses `inliers >= verify_min_locked` (was `locked`), keeping `lock_fraction >= …`, `rms_ms <= …`,
`!clamped`. `core/src/sync.rs::PairFit.windows` becomes `VerifyFit.inliers` (was `.locked`) — its
`off_ms/ppm/rms_ms` were already the verifier's, now over the robust survivors; the §8.4 meaning
change is documented on `PairFit`, the Swift `PairFit`/`VerifyFit` doc comments, and here.

**FFI / Swift.** No C-ABI or wire-shape change: `PairFit.windows` stays a `u32` under the same
`windows` JSON key (only its source value changed), and Phase 1 already added every `VerifyFit`
field (`inliers`/`residualP95Ms`/`temporalCoverage`/`matched`) to `Wire.swift`. So cbindgen was
NOT re-run and `ffi/couple.h` is byte-unchanged this phase. Only Swift DOC comments updated
(`PairFit.windows` and `VerifyFit.inliers` now describe the robust-survivor meaning).

**Decisions / deviations.**
- **Dedup epsilon = one 96-spb bin** (`COARSE_SPB/SR ≈ 2 ms`). That is the finest grid a center
  can resolve at the coarse measurement level, so two centers within one bin would scan the same
  window region — exactly the duplicate evidence §8.1 forbids. `Vec::dedup_by` over the ascending
  linspace removes them.
- **Degenerate-span handling:** `hi − lo < 1e-9` (and `desired == 1`) ⇒ one midpoint, never two

  the max; n = 20 ⇒ the 19th of 20). This matches the convention the deleted `verify.rs` helper
  used, so existing p95 telemetry is continuous.
- **DEVIATION (documented in `robust_fit.rs`): step-6 keep test recenters by the median residual
  `m` — `|resid − m| ≤ threshold`, not the literal `|resid| ≤ threshold`.** Justified by the
  binding §8.5(3) exit gate and invariant 7 (honest uncertainty): a single false lock biases the
  initial fit, shifting EVERY clean residual up by ~`m`; MAD measures only spread so it stays tiny
  and `threshold` collapses to the 2 ms floor — the literal test would then reject the shifted
  clean points too and return `None`, manufacturing a false negative on the exact case §8.5(3)
  requires us to survive. Recentering by `m` (which steps 3–4 already compute and the literal
  reading otherwise leaves unused) is the canonical MAD identifier; it keeps the clean majority
  and drops the outlier (verified: one +30 ms outlier among 11 collinear points ⇒ moves the line

**Cache lifecycle contract (§8.3).**
- *In-decode-pass generation (item 1).* `import::decode_into_cache` already writes PCM/pyramid/onsets;
  after the PCM rename it calls `generate_fingerprint`, which mmaps `pcm48f32.raw` (NO second ffmpeg

  depend on the fingerprint.
- *Old entries stay valid (item 2).* A pre-fingerprint entry has no `.cpf`; `load_meta` ignores the
  sidecar, so it is a normal cache hit. `existing_meta_version_entry_stays_readable` asserts the meta
  carries the current `CACHE_META_VERSION` and validates with the `.cpf` removed.
- *Lazy build from mmap PCM (item 3 / DoD #2).* `TrackData::fingerprint_v1` → `load_or_build(self.cache

- *Atomic install (item 4).* `cache::write_atomic` writes `<cpf>.tmp` then `rename` onto the `.cpf`

  any write error the `.tmp` is removed.
- *Build-at-most-once (item 5).* The success is memoized in `OnceLock<Arc<FingerprintReader>>`; the

  observe the stored `Arc`. After the first success it is a lock-free `OnceLock` read. The contention
  test releases 16 threads through a `Barrier` onto one handle's empty lock and asserts all 16 receive a
  pointer-equal `Arc` ⇒ exactly one build published.
- *Corrupt/incompatible rebuild without harming PCM/pyramid (item 6).* `load_or_build` parses an
  existing `.cpf` under `FingerprintFormatV1::fixed()`. A parse REJECTION (bad checksum / truncation /
  unsorted / out-of-range anchor / mismatched `params_hash`) is treated as "rebuild", never an error:
  it `remove_file`s ONLY the `.cpf`, rebuilds, and reinstalls. `corrupt_fingerprint_rebuilds_pcm_pyramid
  _survive` snapshots PCM+pyramid+meta+onsets and asserts all four are bit-for-bit unchanged after a
  rebuild; `incompatible_params_hash_rebuilds` stages a valid CPF1 written under a different hop
  (different `params_hash`) and asserts it is replaced by a current-format build.
- *GC counts the `.cpf` (item 7).* The sidecar lives inside the entry dir; `cache::list_entries` sums
  ALL files in the dir and `cache::gc` removes the WHOLE entry (`remove_dir_all`). No fingerprint
  special-case. `gc_removes_fingerprint_with_entry` asserts the reported `entry.bytes` equals the sum of
  files in the dir (so the `.cpf` is included) and that GC-to-0 on an unpinned entry deletes the dir and

**Correspondence data contract (§9.2).** `Correspondence{t_a_s, t_b_s, weight}`. For each shared hash
between the video (A) and the selected audio (B):
- WEIGHT = `1/sqrt(occ_a · occ_b)` where `occ_a`/`occ_b` are the hash's per-side occurrence counts. The
  product is `≥ 1`, so the sqrt is finite and the weight is in `(0, 1]` — never NaN/Infinity (§20).
- §9.1 OCCURRENCE-PRODUCT guard applied here: if `occ_a · occ_b > max_occurrence_product` the whole

  `FingerprintBuilder::frame_center_time_s(fmt, frame) = (frame·hop + fft_size/2)/12000 +

  a hard window (§20).
- FRAME-PAIR GROUPING (the fan-out collapse): records sharing one `(a_anchor_frame, b_anchor_frame)` are
  summed into ONE correspondence with `weight = min(1.0, Σ contributing hash weights)`. Done BEFORE the
  cap, so one dense anchor fan-out cannot masquerade as many independent timing observations and inflate
  boundary-5 consensus. (Implementation: accumulate Σweight per `(a_frame, b_frame)` in a transient map,
  then sort the keys by `(a_frame, b_frame)` on EXACT INTEGERS — `frame_center_time_s` is strictly
  increasing in the frame, so integer order IS `(t_a_s, t_b_s)` order, computed without float comparison
  — and clamp Σ to 1.0 when materializing the times.)
- CAP — the 128-bin TIME-STRATIFIED sample: if the grouped count exceeds
  `max_correspondences_per_pair`, divide A's duration into 128 equal bins by `t_a_s` (the usable span is
  `[t(frame 0), t(last frame)]` from `duration_frames`, falling back to the empirical `t_a_s` max so the
  span is always `> 0` and finite ⇒ no div-by-zero/NaN); allocate the cap proportionally to each bin's
  population with `≥ 1` from every non-empty bin (largest-remainder distribution of the leftover after
  the guaranteed 1s and the integer-floor proportional shares, tie-broken by earlier bin); within a bin
  retain the HIGHEST-weight members (tie-break `t_a_s`, then `t_b_s`, then a stable integer index); then
  re-sort the union by `(t_a_s, t_b_s)`. When `cap < non-empty-bin-count` it cannot honor ≥1-per-bin, so
  it places one slot into each of the `cap` MOST-POPULATED non-empty bins (deterministic, still spread
  across the timeline) — never a first-N prefix (§20). `CorrespondenceStats` records
  `raw_pairs`, `grouped`, `kept`, `capped`, plus the product-drop counts. Final output is sorted by
  `(t_a_s, t_b_s)`.
