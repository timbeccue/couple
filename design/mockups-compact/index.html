Couple · compact mode prototypes

Three directions for a window about the width of one sidebar. Same engine, same rows (the bach session from mockups-v2: three good couples, one that needs a pick, one with no match). Each one keeps import → auto-sync → review → export and drops the loupes, waveform stage and nudge tools; those stay one click away in the full window. Use the state buttons under each to step through the session.

What differs between the three

  • D · Fixed preview + list (round 3) — the selected couple's player (or its audio picker) sits in a fixed block at the top; the list below only scrolls rows. No status dots anywhere: good rows are just a name and a checkbox, flagged rows say “pick one” or “no audio”. Export is the A panel (into / as / keep camera audio) with “This one” and “Export N files” side by side; the checkbox is what counts toward N.
  • A · List — the queue rail on its own. Good couples are pre-checked for export; selecting a row opens a small player inline so you can listen before exporting, but nothing requires it. Closest to the current app; least to learn.
  • B · Cards (reworked 2026-11-04) — implicit approval. A green verdict is the gate: the couple is in “Export all” unless skipped. Each card has Listen, Export (this one) and a hover Skip; exported couples carry a ✓ and time, and “Export all” counts only what is left. Flagged couples (pick one / no audio) are excluded and the footer says so.
  • Full window · queue rail — the same rule applied to the existing window: Ready / To fix, no QUEUED FOR EXPORT section, no checkboxes, no Approve button or v key.
  • C · Drop & go — a drop target that turns into a one-line summary and an Export button. The list is behind a disclosure; the only thing that interrupts you is a couple that needs a pick. Smallest window, fewest decisions.
